Start / zzp

Your first prime field: zzp

zzp is the easiest entry point into NTL.jl. It represents arithmetic modulo a machine-word prime p. Think of zzp{7} as the finite field containing exactly seven elements, written with representatives 0,1,2,3,4,5,6.

Four words worth knowing

modulusThe prime p that defines the field. It is also the field characteristic.
elementA residue class modulo p. For example, 8 and 1 denote the same element modulo 7.
representativeThe canonical integer stored in 0:p-1. Use rep(a) or Int(a) to inspect it.
parentThe field to which an element belongs. For zzp, the parent is the type zzp{p} itself.

Construct, calculate, and read the output

A complete first session
using NTL

F = zzp(7)       # F is zzp{7}
a = F(10)        # 10 mod 7 = 3
b = F(-1)        # -1 mod 7 = 6

println(a)       # zzp{7}(3)
println(a + b)   # zzp{7}(2)
println(a * b)   # zzp{7}(4)
println(a / b)   # zzp{7}(4), because 3*inv(6) = 18 = 4 mod 7

@assert rep(a) == 3
@assert Int(a) == 3
@assert modulus(a) == 7
@assert a * inv(a) == one(F)
@assert a^0 == one(F)

The displayed form zzp{7}(3) therefore means “the element with representative 3 in the field modulo 7.” Integer operands are reduced automatically, so a+20 and 2a are valid.

Iterate over every field element

A zzp field is a finite Julia iterator. Elements are produced in canonical order, beginning with zero and ending with p-1.

Iteration, collection, and summation
F = zzp{5}

for a in F
    println(a)
end

@assert [rep(a) for a in F] == [0,1,2,3,4]
@assert collect(F) == F.([0,1,2,3,4])
@assert length(F) == 5
@assert first(F) == F(0)
@assert last(F) == F(4)
@assert sum(F) == F(10)

Large fields. Iteration is lazy and does not allocate a vector. collect(F) does allocate p elements, so do not collect a very large field merely to test its size; use length(F) instead.

Choose zzp or ZZP

NeedRecommended parent
Small, prime modulus fitting in IntF = zzp(p). Fast machine-word storage, type-level modulus, and finite-field iteration.
Arbitrarily large modulusF = ZZP(n). BigInt storage and an explicit runtime parent.
Composite modulus for ring arithmeticZZP(n). Addition and multiplication work; only units have inverses. zzp deliberately rejects composite moduli.
Enumerate all elementszzp(p). Iteration is defined only for the machine-word prime-field parent.

Beginner checklist and common errors

  • zzp(15) throws ArgumentError because 15 is composite. Use ProbPrime(p) when you need a Boolean primality check first.
  • F(2) is zero when F=zzp(2). Construction always reduces modulo the field modulus.
  • Division or a negative power requires a nonzero denominator/base. inv(zero(F)) throws DomainError.
  • Different moduli are different parents. Do not add zzp{7}(1) to zzp{11}(1) without explicitly choosing the mathematics you intend.
  • Use iszero(a), isone(a), zero(F), and one(F) rather than relying on visual output.

03 / ZZ

Arbitrary-precision number theory

ProbPrime is deterministic for signed machine integers and uses fixed Miller–Rabin witnesses for larger integers. FactorInt combines primality testing with Brent's batch-GCD variant of Pollard rho. The output is a sorted vector of (prime, exponent) pairs.

examples/04_number_theory.jl — excerpt
n = big(2)^89 - 1
@assert ProbPrime(n)

fac = FactorInt(big(99991) * big(10007))
@assert prod(p^e for (p,e) in fac; init=BigInt(1)) == big(99991)*big(10007)

x, M = CRT([2,3,2], [3,5,7])
@assert (x,M) == (23,105)

r = SqrRootMod(10, 13)
@assert r !== nothing && r^2 % 13 == 10

g = PrimitiveRoot(97)
y = powermod(g, 42, 97)
@assert powermod(g, DiscreteLog(g,y,97), 97) == y
GenPrime(bits)Random probable prime with an exact requested bit length.
RandomBits / RandomLen / RandomBndSeeded AbstractRNG support for reproducible arbitrary-precision random integers.
SqrRootModTonelli–Shanks for odd primes, with characteristic-two and nonresidue cases.
DiscreteLogBaby-step/giant-step logarithms in prime-field multiplicative groups.
04 / Polynomials

From Euclidean arithmetic to factorization

Coefficients are stored from low degree to high degree, and trailing zeros are normalized. The zero polynomial has degree -1. Constructors accept any supported parent, including an extension-field object.

Factorization over F_97
F = zzp(97)
x = xpoly(F)
f = (x+1)^3 * (x^2+x+1) * (x^4+3x+5)
fac = factor(f; rng=MersenneTwister(2026))

@assert reconstruct(fac) == f
@assert all(is_irreducible(g) for (g,m) in fac.factors)

m = BuildIrred(F, 6)
a = PowerMod(x+1, big(10)^100, m)

Binary polynomials and extension fields

GF(2^8) with the AES polynomial
x = GF2X(2)  # bit i stores coefficient x^i
m = x^8 + x^4 + x^3 + x + 1
E = GF2E(m)
a = gen(E) + 1

@assert cardinality(E) == 256
@assert a^255 == one(E)
@assert a * inv(a) == one(E)
Generic extension-field polynomials. xpoly(E) creates another polynomial layer over an extension. The same arithmetic and finite-field factorization algorithms then operate on ExtensionElem coefficients.
05 / Exact linear algebra

Matrices and LLL with checkable invariants

Field matrices use pivoting and Gauss–Jordan elimination. Integer determinants use fraction-free Bareiss elimination. LLL uses exact rational Gram–Schmidt data, size reduction, and the Lovász condition.

examples/07_matrix_lattice.jl — excerpt
F = zzp(101)
A = F.([2 3 1; 4 1 5; 3 7 2])
b = F.([1,2,3])
@assert A * solve(A,b) == b
@assert A * matrix_inverse(A) == F.([1 0 0; 0 1 0; 0 0 1])

A0 = BigInt[1 1 1; -1 0 2; 3 5 6]
reduced = lll(A0)
B, U = reduced.basis, reduced.transform
@assert U * A0 == B
@assert abs(det_exact(U)) == 1

LLL accepts full-rank integer row bases. The returned transformation makes the result independently checkable without relying on approximate floating-point reconstruction.

06 / NTT

Primitive roots and fast convolution

The radix-two transform requires a power-of-two length n dividing p-1. ntt_convolve chooses the next power of two for the linear-convolution length and throws a clear error if the selected field cannot support it.

examples/08_ntt_convolution.jl
F = zzp(257)       # 257-1 = 256
omega = root_of_unity(32, F)
a = rand(MersenneTwister(2026), F, 32)
@assert intt(ntt(a)) == a

u = rand(MersenneTwister(7), F, 100)
v = rand(MersenneTwister(8), F, 80)
@assert ntt_convolve(u,v) == convolve(u,v)

09 / Speed

Optional polynomial acceleration

Acceleration is enabled by default. It selects Karatsuba for medium degrees and NTT for large supported prime fields; the original schoolbook remains available as an explicit opt-out. If the required NTT length does not divide p-1, the implementation falls back to Karatsuba.

Default acceleration and original fallback
using NTL

set_polynomial_acceleration!(true)
@assert polynomial_acceleration()

F = zzp(998244353)
f = random_poly(F, 600)
g = random_poly(F, 600)
result = poly_mul(f, g)

set_polynomial_acceleration!(false)

Compare each path

Explicit method selection
reference = poly_mul(f, g; method=:schoolbook)
@assert poly_mul(f, g; method=:karatsuba) == reference
@assert poly_mul(f, g; method=:ntt) == reference
@assert poly_mul(f, g; method=:auto) == reference

The machine-word NTT kernel uses in-place radix-two butterflies with cached roots and raw representatives. This avoids repeated modulus checks and temporary field objects in the hot loop.

09 / Scope

What is—and is not—claimed

This is a broad, independently tested mathematical core, not a line-for-line or performance-complete replacement for every NTL module.

  • No C++ ABI compatibility and no attempt to reproduce NTL's global context stack. Parents and Julia type parameters carry the mathematical context instead.
  • RR, quad_float, and xdouble are not reimplemented; Julia's BigFloat is the recommended arbitrary-precision real layer.
  • Hermite normal form, full integer-polynomial factorization, Schnorr–Euchner/BKZ reduction, and NTL's platform-specific SIMD or assembly optimizations are not included in version 0.7.0.
  • The exact LLL implementation prioritizes reproducibility and correctness for modest bases, not NTL's highly tuned large-basis throughput.
  • Polynomial acceleration is enabled by default; schoolbook can be selected explicitly or restored with set_polynomial_acceleration!(false).

Evaluation principle. Every advertised workflow is runnable from the delivered package. The test command and examples are the demonstration, rather than screenshots of unverified output.
